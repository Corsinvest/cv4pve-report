Some of the columns only. Health is the [0-100 score](/cv4pve-report/output/#health-score) of the resource; a
stopped VM has none. Without a running guest agent, Os Version is the OS type set in the VM configuration.

Two pages the Proxmox VE web interface has no equivalent for.
[Partitions](/cv4pve-report/sections/storage/#partitions) is the space used inside each VM, read from
the guest agent: Proxmox VE itself reports no disk usage for VMs.
[Capacity Planning](/cv4pve-report/sections/capacity-planning/) (on with `--full`) is the
average and the peak of each guest and node over a week, with the growth of every storage: `erp01`
above averages 2 % of its CPUs and peaks at 92 %.
:::tip[Tested at scale]
A production cluster of **25 nodes and about 2700 VMs** gets its full report in **about 7 minutes**
with `MaxParallelRequests: 10`, and in [12.7 minutes](https://github.com/Corsinvest/cv4pve-report/issues/10#issuecomment-4422977335) with the default of 5, measured by
[its administrator](https://github.com/Corsinvest/cv4pve-report/issues/10#issuecomment-4432966790) on version 2.x, with the per-VM detail sheets off. See
[Performance](/cv4pve-report/settings/#performance).
:::

## Why

The Proxmox VE web interface shows one object at a time: a VM's hardware on one tab, its snapshots on
another, the storage it lives on somewhere else. That is fine for daily work, but not when someone asks
*how many VMs do we run, on which nodes, with how much memory, and who can log in?* (an auditor, a
customer taking over the cluster, a capacity plan, a migration from VMware).

cv4pve-report reads the whole cluster and writes it down in one file you can filter, share and keep.
Take one every month and you have the history of the cluster: what was running, where, and when.

## Where it fits

The cv4pve suite follows the Unix philosophy: each tool does one thing and does it well. cv4pve-report
exports everything the cluster contains, to read, share and keep. Its companion
[cv4pve-diag](https://corsinvest.github.io/cv4pve-diag/) finds what is wrong. Two questions, two tools,
used together.

| | **cv4pve-report** | [cv4pve-diag](https://corsinvest.github.io/cv4pve-diag/) |
|---|---|---|
| **Question** | What do I have? | What is wrong? |
| **Purpose** | Inventory and reporting | Diagnostics and health checks |
| **Result** | The full inventory: nodes, VMs, containers, storage, network, users… | A list of problems, each with a code, a severity and the resource it concerns |
| **Formats** | Excel, static HTML site, multi-file JSON, plus an SVG network diagram | Text, HTML, JSON, Markdown, Excel |
| **Compliance** | - | Findings tagged with the controls of 18 standards |
| **Access** | Proxmox VE API only, from outside the nodes | Proxmox VE API only, from outside the nodes |

## Outside the nodes, API only

cv4pve-report runs outside the cluster (on your workstation, a management VM or a scheduled job) and
talks only to the Proxmox VE REST API. Nothing is installed on the nodes and no SSH or root shell is
needed: an API token with the privileges listed in [Permissions](/cv4pve-report/permissions/) is enough.
Any node gives the view of the whole cluster; give it more than one and it connects to the first one that
answers, so it still runs while a node is down.
