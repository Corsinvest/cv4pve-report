These sections are the guest inventory: every QEMU VM and LXC container with its sizing, live usage, guest-agent data,
configuration, disks, filesystems and snapshots. Use them to find VMs without a working guest agent, disks on the wrong
storage or with backup disabled, filesystems close to full and snapshots nobody cleaned up.

How to read the tables:

- **Excel / HTML** is the column header, the same in both formats. **JSON** is the key in the JSON file.
- **Sizes** — `GB` or `MB` in the header — are in that unit in Excel and HTML, and raw bytes in JSON.
- **Percentages** — `%` in the header — are formatted as percentages in Excel and HTML; JSON has the raw
  value, a fraction from 0 to 1 for usage columns.
- **Flags** show `X` in Excel, `✓` or `·` in HTML, `true` or `false` in JSON.
- **Multi-line cells** hold one value per line; in JSON they are a string with line breaks (`\n`, or
  `\r\n` when the report was generated on Windows).
- **Links** to other pages exist in Excel and HTML; JSON has the plain value. Empty values are `null`
  or `""` in JSON.
- **Dates and times** are in UTC.
- How the JSON files are shaped: see [JSON](/cv4pve-report/output/json/#shapes).

## Which guests

Every section on this page covers only the guests selected by `Guest.Ids` (default `@all`) — see
[Choosing nodes and guests](/cv4pve-report/settings/#choosing-nodes-and-guests). Rows are sorted by ID,
with numbers compared as numbers. In every table, **Node** links to the node's page and **Vm Id** to the
guest's page; in Disks, **Storage** links to the Storages section.

## VMs

Excel sheet `VMs` · HTML `vms.html` · JSON `vms.json` · always generated, limited by
[`Guest.Ids`](/cv4pve-report/settings/); agent data by [`Guest.IncludeQemuAgent`](/cv4pve-report/settings/) and
[`Guest.QemuAgentTimeout`](/cv4pve-report/settings/).

For each VM the report reads `/nodes/{node}/qemu/{vmid}/config`. A VM whose status is `unknown` still gets a row,
but its config is not read and the config columns stay empty. The guest agent is queried only when **all** of these
are true:

1. the VM is running;
2. `agent` is enabled in its config;
3. `Guest.IncludeQemuAgent` is `true`.

The report first calls `agent/info`. If the agent does not answer within `Guest.QemuAgentTimeout` seconds (default
3), it counts as not running. If it answers, the report calls `get-osinfo`, `get-host-name`,
`network-get-interfaces` and `get-fsinfo` in parallel.

:::note[What the Hostname column tells you]
Hostname comes from the guest agent. For a running VM it can also hold a status message:
`Agent not enabled!` (agent off in the VM config), `Agent timeout!` (no answer within the timeout), or
`Agent not running! (<error>)` (the call failed, and a warning is also added to the Issues page).
:::

When the agent is running and reports interfaces, the network columns show the interfaces the guest reports,
matched to the config NICs by MAC address. Interfaces with no MAC or an all-zero MAC are skipped. Guest-only
interfaces (no matching NIC in the config) are left out of this table but passed to the Network section. When the
agent is not running, or returns no interfaces, the NICs come from the config, and a QEMU config has no IP
addresses. A configured NIC that the agent does not report is taken from the config too.

## Containers

Excel sheet `Containers` · HTML `containers.html` · JSON `containers.json` · always generated, limited by
[`Guest.Ids`](/cv4pve-report/settings/).

For each container the report reads `/nodes/{node}/lxc/{vmid}/config`, except containers whose status is `unknown`.
It never uses an agent. For a **running** container it also reads `/nodes/{node}/lxc/{vmid}/interfaces` and matches
the live interfaces to the config NICs by MAC address. For each NIC, the live addresses (link-local `fe80…`
excluded) are used like this:

- configured as `dhcp`, `auto` or `manual`: the live address followed by the mode, e.g. `10.0.0.5/24 (dhcp)`;
- no address configured: the live address;
- static address configured: the configured value is kept.

If the endpoint is missing (older Proxmox VE releases) or fails, the configured values are shown and no issue is raised.

## Snapshots

Excel sheet `Snapshots` · HTML `snapshots.html` · JSON `snapshots.json` · enabled by
[`Guest.IncludeSnapshots`](/cv4pve-report/settings/).

Snapshots of every selected VM and container whose status is not `unknown`, read from
`/nodes/{node}/qemu|lxc/{vmid}/snapshot`. Rows are sorted by guest, then by snapshot time. If a guest's snapshot list
cannot be read, a warning goes to the Issues page and the guest is skipped. The `current` entry that Proxmox VE
returns for the running state is not a snapshot and is left out.
