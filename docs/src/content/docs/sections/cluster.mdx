These sections cover everything configured at datacenter level: quorum and membership, backup and replication jobs, storage definitions, users, tokens and ACLs, SDN, HA, pools, plus the cluster log and task history.
Read them when you audit who can do what, check that backup jobs cover the right guests, or need a record of the datacenter configuration before a change.

<ReadingTables />

## Cluster

Excel sheet `Cluster` · HTML `cluster.html` · JSON `cluster.json` · enabled by `Cluster.Include` (see [/cv4pve-report/settings/](/cv4pve-report/settings/)).

Data comes from `/cluster/status`, `/cluster/options`, `/cluster/firewall/options`, `/cluster/backup`, `/cluster/replication`, `/storage`, `/cluster/metrics/server` and `/cluster/mapping/{dir,pci,usb}`.

### Cluster

Key/value block at the top of the section, titled Cluster in Excel and Info in HTML. In JSON it is the `info` object.

| Excel / HTML | JSON | Content |
|---|---|---|
| Name | `name` | Cluster name; `-` when `/cluster/status` has no `cluster` entry (standalone node) |
| Nodes | `nodes` | Number of nodes reported by the cluster entry |
| Version | `version` | Cluster configuration version |
| Quorate | `quorate` | `Yes` or `No` |

### Status

One row per `/cluster/status` entry: the cluster entry first, then the nodes sorted by name.

| Excel / HTML | JSON | Content |
|---|---|---|
| Id | `id` | Entry id |
| Name | `name` | Cluster or node name |
| Is Online | `isOnline` | Flag: node is online |
| Type | `type` | `cluster` or `node` |
| Nodes | `nodes` | Node count (cluster entry) |
| Version | `version` | Cluster configuration version (cluster entry) |
| Quorate | `quorate` | Quorum value as returned by the API (number) |
| Level | `level` | Subscription level decoded to its name (Community, Premium, Basic, ...) |
| Ip Address | `ipAddress` | Node IP address |
| Node Id | `nodeId` | Corosync node id |

## Cluster Access

Excel sheet `Cluster Access` · HTML `cluster-access.html` · JSON `cluster-access.json` · enabled by `Cluster.Include` (see [/cv4pve-report/settings/](/cv4pve-report/settings/)).

Data comes from `/access/users` (with `full`), `/access/tfa`, `/access/groups`, `/access/roles`, `/access/acl` and `/access/domains`. Every table is sorted by its first column.

### Users

| Excel / HTML | JSON | Content |
|---|---|---|
| Id | `id` | User id (`user@realm`) |
| Enable | `enable` | Flag: account enabled |
| Firstname | `firstname` | First name |
| Lastname | `lastname` | Last name |
| Email | `email` | Email |
| Groups | `groups` | Groups the user belongs to |
| Keys | `keys` | Two-factor keys field |
| Totp Locked | `totpLocked` | Flag: TOTP locked after too many failed attempts |
| Tfa Locked Until | `tfaLockedUntil` | Date and time until which TFA is locked; empty when not locked |
| Expire | `expire` | Account expiry date and time; empty when the account never expires |
| Comment | `comment` | Comment (wrapped) |

### API Tokens

One row per API token of each user. JSON key `apiTokens`.

| Excel / HTML | JSON | Content |
|---|---|---|
| User | `user` | Owner user id |
| Token Id | `tokenId` | Token name |
| Expire | `expire` | Expiry date and time; empty when the token never expires |
| Priv Separated | `privSeparated` | Flag: privilege separation enabled |
| Comment | `comment` | Comment (wrapped) |

### Two-Factor Authentication

One row per user with TFA entries. JSON key `twoFactorAuthentication`.

| Excel / HTML | JSON | Content |
|---|---|---|
| User | `user` | User id |
| Tfa Types | `tfaTypes` | Distinct TFA types, comma separated |
| Tfa Count | `tfaCount` | Number of TFA entries |

### Groups

| Excel / HTML | JSON | Content |
|---|---|---|
| Id | `id` | Group id |

### Roles

| Excel / HTML | JSON | Content |

| Privileges | `privileges` | Privileges, one per line |

| Excel / HTML | JSON | Content |

### Domains

One row per authentication realm.

| Excel / HTML | JSON | Content |

## Cluster Pools

Excel sheet `Cluster Pools` · HTML `cluster-pools.html` · JSON `cluster-pools.json` · enabled by `Cluster.Include` (see [/cv4pve-report/settings/](/cv4pve-report/settings/)).

### Pools

One row per pool member: the report reads `/pools`, then `/pools/{poolid}` for each pool. A pool without members produces no row. This is the only table of the section, so `cluster-pools.json` is a plain array of rows.

| Excel / HTML | JSON | Content |
|---|---|---|
| Pool | `pool` | Pool id |
| Type | `type` | Member type (qemu, lxc, storage) |
| Node | `node` | Node of the member, hyperlinked to the node |
| Vm Id | `vmId` | Guest id, hyperlinked to the guest (no link for storage members) |
| Storage | `storage` | Storage id, hyperlinked to the Storages section |
| Status | `status` | Member status |
| Description | `description` | Member description (wrapped) |
| Comment | `comment` | Pool comment (wrapped), repeated on each member row |

## Cluster Log

Excel sheet `Cluster Log` · HTML `cluster-log.html` · JSON `cluster-log.json` · enabled by `Cluster.Log.Enabled` (see [/cv4pve-report/settings/](/cv4pve-report/settings/)).

This section does not depend on `Cluster.Include`. Entries come from `/cluster/log`; when `Cluster.Log.MaxCount` is greater than 0 it is passed as the `max` parameter, otherwise the API default applies.

The section has one untitled table, so `cluster-log.json` is a plain array of rows.

| Excel / HTML | JSON | Content |
|---|---|---|
| Time Date | `timeDate` | Date and time of the entry |
| Node | `node` | Node, hyperlinked to the node |
| User | `user` | User |
| Severity Enum | `severityEnum` | Severity name (Panic, Alert, Critical, Error, Warning, Notice, Info, Debug) |
| Service | `service` | Service (log tag) |
| Message | `message` | Log message |
